# PHP: общие правила

Общие правила проекта — в [AGENTS.md](../../AGENTS.md).

- Соблюдать **WordPress Coding Standards (WPCS)**.
- После каждого изменения PHP запускать PHPCBF для автоматического исправления всех затронутых PHP-файлов, затем
	проверять их через PHPCS по WPCS. Оставшиеся нарушения исправлять вручную и повторять PHPCS до успешной проверки.
	Если инструменты недоступны или проверку запустить не удалось, сообщить об этом в итоговом сообщении.
- Для вывода nonce-полей в формах использовать `adem_wp_nonce_field()`, а не `wp_nonce_field()`:
	хелпер убирает `id` у nonce-поля, чтобы несколько форм на странице не создавали одинаковые ID.
- Если внутри `if`, `foreach`, `while` и подобных конструкций нет HTML-разметки, использовать фигурные скобки `{}`.
	Альтернативный синтаксис (`endif;`, `endforeach;` и т.д.) оставлять только для участков шаблона с HTML внутри
	конструкции.
- Все ACF-поля, используемые в шаблоне, выносить в переменные **в начале файла**, а не вызывать `get_field()` /
	`get_sub_field()` посреди разметки.
- Изображения из ACF возвращаются в формате `id` (не array, не url).
	- Для обычного вывода: `adem_dynamic_thumbnail( $id, $width, $height, $crop, $attr )`
	- Для полного размера: `wp_get_attachment_image( $id, 'full' )`
- При выводе HTML из `adem_dynamic_thumbnail()` всегда оборачивать вызов в `wp_kses_post()`.
- Не проверять ID перед отдельным вызовом `wp_get_attachment_image()`: при пустом ID функция возвращает пустую строку.
	Условие сохранять, если от наличия изображения зависит вывод окружающего контейнера или структура блока.
- Для повторяющихся элементов разметки использовать `get_template_part()`:
	- карточки → `layouts/cards/`
	- партиалы → `layouts/partials/`
- Файлы карточек в `layouts/cards/` называть по шаблону `name-card.php`, где `name` — короткое слово,
	характеризующее карточку (например, `service-card.php`).
- Если к массиву элемента нужно добавить аргументы для `get_template_part()` (например, CSS-класс карточки), передавать
	результат `array_merge()` непосредственно в вызов. Не изменять исходный массив элемента перед вызовом.
- Не использовать `nl2br()` и `white-space: pre-line` для переносов строк из ACF-полей.
- Не использовать `wpautop()` для вывода ACF-текста: пользователь добавляет нужные HTML-теги вручную, выводить
	разрешённую разметку через `wp_kses_post()`.

## Массивы

Пример передачи дополнительного класса карточке:

```php
get_template_part(
	'layouts/cards/adv-card',
	null,
	array_merge(
		$card,
		array(
			'class' => 'why__card',
		)
	)
);
```

- Если в вызове функции среди аргументов есть непустой массив, оформлять вызов многострочно: каждый аргумент на
	отдельной строке, закрывающая скобка — на отдельной строке. Пустой массив `array()` или `[]` сам по себе не требует
	переноса;
	объявления функций это правило не затрагивает.
- PHP-массивы с несколькими элементами (например, аргументы для `get_template_part()`) писать не в одну строку, а каждый
	элемент — на отдельной строке, с закрывающей скобкой на новой строке:

```php
array(
	'items' => $footer_socials,
	'class' => 'footer__social',
)
```

## Атрибуты HTML-тегов

- В шаблонах не использовать тег `<p>`, если пользователь явно не попросил его; для обычного текстового блока
	использовать `<div>`.
- Если атрибуты открывающего тега не помещаются в 120 символов — переносить их на новую строку, но **не по одному
	атрибуту на строку**: первый атрибут остаётся на строке с тегом, остальные обычные атрибуты переносятся одним блоком
	на следующую строку (через пробел, как обычно).
- Закрывающий `>` открывающего тега **всегда** оставлять на строке с последним атрибутом, в том числе если последний
	атрибут относится к Alpine.js (`@click`, `x-show`, `x-cloak`, `x-transition` и т.д.). Не писать `>` отдельной строкой.
- Атрибуты, относящиеся к Alpine.js (`x-data`, `x-show`, `x-on:...` / `@...`, `x-bind:...` / `:...`, `x-transition` и
	т.д.), писать **каждый на отдельной строке**, и располагать их **после** обычных атрибутов.

Пример (обычные атрибуты):

```php
<img src="<?php echo esc_url( get_template_directory_uri() . '/assets/images/logo.svg' ); ?>" width="226" height="50"
		alt="Светлана">
```

Пример (обычные атрибуты + Alpine.js):

```php
<div class="block-name__panel" id="panel"
	x-data="{ open: false }"
	x-show="open"
	@click.outside="open = false">
```

## Чего НЕ делать

- Не вызывать `get_field()`/`get_sub_field()` россыпью по шаблону — только переменные в начале файла.
- Не выводить ACF-изображения напрямую через `wp_get_attachment_image_url()` или `<img src="...">` — только через
	`adem_dynamic_thumbnail()` или `wp_get_attachment_image( $id, 'full' )`.
- Не писать Alpine.js-атрибуты (`x-data`, `x-show`, `@click` и т.д.) в одну строку с другими атрибутами тега — каждый на
	своей строке.
- Не писать многоэлементные PHP-массивы в одну строку — каждый элемент на отдельной строке.
