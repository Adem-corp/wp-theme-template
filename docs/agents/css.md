# CSS

Общие правила проекта — в [AGENTS.md](../../AGENTS.md).

- Методология БЕМ для классов блоков и компонентов. Существующие служебные классы (`.container`, `.hidden`,
	`.clearfix`, `.reset-list`) остаются исключением.
- В названиях классов для изображений использовать `img`, а не `image` (например, `block-name__img`); для кнопок —
	`btn`, а не `button` (например, `block-name__btn`).
- SCSS, линтинг — собственный `.stylelintrc.json`. После каждого изменения SCSS запускать Stylelint для всех
	затронутых SCSS-файлов с этой конфигурацией и исправлять ошибки до завершения задачи. Если проверку запустить
	не удалось, сообщить об этом в итоговом сообщении.
- `.editorconfig`: табуляция, `indent_size = 2`.
- `line-height` всегда указывать относительным числом без единиц (например, `1.4`), не в процентах и не в пикселях.
- Для парных отступов по осям использовать `padding-block`, `padding-inline`, `margin-block` и `margin-inline`
	вместо сокращений вроде `padding: 16px 0`. Для отдельных сторон использовать обычные свойства `margin-top`,
	`padding-right` и т.п.; не заменять их на `*-block-start`, `*-inline-end` и аналоги. Общий сброс всех отступов
	(`margin: 0`, `padding: 0`) можно оставлять сокращённым.
- Для блоков с необязательной соседней колонкой (например, текст и цитата) использовать flex: основной контент
	должен автоматически занимать свободную ширину, если соседнего элемента нет. Не добавлять условный класс только
	для переключения количества колонок.

## Вложенность селекторов

- Модификаторы (`&--...`) располагать сразу после собственных стилей класса, к которому они относятся, включая его
	`@include`-миксины, и перед вложенными элементами. Например, модификатор блока `&--vip` должен находиться в начале
	блока после его основных стилей, а не в конце после всех `&__...`.
- Не объединять модификатор блока и его элемент в конструкции вида `&--3 &__card`.
- Внутри модификатора блока писать отдельный вложенный селектор с полным классом элемента.

Неправильно:

```scss
.simple-cards {
	&--3 &__card {
		flex-basis: calc((100% - 48px) / 3);
	}
}
```

Правильно:

```scss
.simple-cards {
	&--3 {

		.simple-cards__card {
			flex-basis: calc((100% - 48px) / 3);
		}
	}
}
```

## Списки

- Если у `<ul>` нужно сбросить `margin`, `padding` и `list-style` — по возможности вешать готовый класс `.reset-list`, а
	не прописывать сброс вручную в стилях блока.

## Кнопки

- Общие стили кнопок хранить в отдельном файле — `components/_buttons.scss`.
- Кнопка — самостоятельный компонент: базовые стили (вид, паддинги, цвета, hover через `@include hover`) описываются в
	`_buttons.scss`, а не дублируются внутри стилей блока.
- Позиционирование кнопки относительно родителя (например, отступы, выравнивание внутри блока) прописывается в
	классе-контейнере блока (`block-name__btn`), а не в самом классе кнопки.

## Меню

- Стили всех меню хранить в одном файле — `components/_menus.scss`.
- Класс каждого меню начинается с `menu-`, далее указывается его расположение: `menu-main`, `menu-burger`, `menu-footer`
	и т.д.
- Меню — это самостоятельный компонент: его собственные стили (`.menu-main`, `.menu-burger` и т.д. в `_menus.scss`) не
	должны включать позиционирование этого меню относительно родителя (`position`, `grid-column`, `margin` для размещения
	и т.п.).
- Стили, отвечающие за расположение конкретного меню внутри блока (например, меню внутри `header`), прописываются в
	классе-контейнере этого блока (`header__menu`), а не в классе самого меню.

## Переменные

- Шрифты задавать через CSS custom properties `--font-...` из `_variables.scss`.
- Цвета брать точно из макета. Если значение совпадает с существующей переменной `--color-...`, использовать её;
	если подходящей переменной нет — указывать точное значение цвета из макета напрямую.
- Не использовать `color-mix()` и не подбирать приближённые цвета смешиванием: указывать цвет, заданный в дизайне.

## Hover

- Для псевдокласса `:hover` использовать миксин `@include hover`, а не писать `&:hover` напрямую.

```scss
&__btn {
	@include hover {
		background: var(--color-accent);
	}
}
```

## Медиазапросы

- Для медиазапросов использовать существующие миксины (`@include laptop(...)`, `@include mob(...)` и т.п.).
- Миксин обязательно должен быть **внутри конкретного селектора**, вокруг тех свойств, которые меняются, а не
	оборачивать сразу несколько селекторов одним блоком `@include`.
- Между обычными свойствами и `@include` (и между несколькими `@include` подряд) пустых строк не оставлять — писать без
	отступов, единым блоком.

Неправильно:

```scss
@include to(1200px) {
	&__logo {
		flex-basis: 160px;
	}

	&__menu {
		gap: 12px;
	}
}
```

Также неправильно (пустые строки между свойствами и миксинами):

```scss
&__panel {
	display: flex;
	gap: 20px;

	@include to(1200px) {
		gap: 16px;
	}

	@include tablet {
		display: none;
	}
}
```

Правильно:

```scss
&__logo {
	@include to(1200px) {
		flex-basis: 160px;
	}
}

&__menu {
	@include to(1200px) {
		gap: 12px;
	}

	a {
		@include to(1200px) {
			font-size: 11px;
		}
	}
}

&__panel {
	display: flex;
	gap: 20px;
	@include to(1200px) {
		gap: 16px;
	}
	@include tablet {
		display: none;
	}
}
```

## Чего НЕ делать

- Не указывать шрифты напрямую в коде — только через переменные из `_variables.scss`.
- Не использовать `color-mix()` или приближённые цвета вместо точных значений из макета.
- Не оборачивать медиазапросом (`@include to(...)`) сразу несколько селекторов — миксин должен быть внутри каждого
	отдельного селектора, вокруг конкретных свойств.
- Не писать `&:hover` напрямую — использовать миксин `@include hover`.
- Не оставлять пустые строки между свойствами и `@include`-миксинами внутри селектора.
- Не прописывать позиционирование меню (относительно родительского блока) внутри класса `.menu-*` — это задача
	класса-контейнера (`header__menu` и т.п.).
- Не дублировать базовые стили кнопок внутри блоков — общие стили кнопок только в `components/_buttons.scss`.
- Не сбрасывать `margin`/`padding`/`list-style` у `<ul>` вручную в стилях блока — использовать класс `.reset-list`.
